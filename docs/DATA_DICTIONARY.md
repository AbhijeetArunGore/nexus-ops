# NEXUS Ops — Data Dictionary & Entity Specifications

---

## 1. Normalized Log Event Schema (`LogEvent`)

Every ingested raw line (JSON, Java Log4j/Logback, Python trace, Syslog, HTTP access) is transformed into this standard model:

| Field Name | Type | Nullable? | Description | Example Value |
| :--- | :--- | :---: | :--- | :--- |
| `id` | UUID (v4) | No | Database primary key. | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| `incident_id` | UUID (v4) | No | Foreign key linking event to parent incident. | `e1b7643b-74a9-467f-94ad-32328ff4e209` |
| `event_id` | String | No | Sequential human-readable identifier within incident. | `EVT-0001` |
| `timestamp` | DateTime | Yes | Extracted ISO-8601 UTC timestamp. Explicitly null if missing. | `2026-11-18T10:00:15.350Z` |
| `service` | String | No | Originating microservice name. | `payment-api` |
| `environment` | String | No | Fixed simulated environment identifier. | `simulated` |
| `log_level` | Enum | No | Normalized level: `CRITICAL`, `ERROR`, `WARN`, `INFO`, `DEBUG`. | `ERROR` |
| `message` | Text | No | Sanitized log message text with redaction masks applied. | `Connection timeout waiting for bank-connector` |
| `error_type` | String | Yes | Classification of exception or error class. | `TimeoutError` |
| `trace_id` | String | Yes | W3C distributed trace identifier. | `tr-9001-abc` |
| `span_id` | String | Yes | Specific RPC span identifier. | `sp-101` |
| `transaction_id`| String | Yes | Unique payment transaction identifier. | `SYN-TXN-8801` |
| `endpoint` | String | Yes | HTTP route or RPC method invoked. | `/payments/v1/order` |
| `http_status` | Integer | Yes | HTTP response status code. | `504` |
| `duration_ms` | Float | Yes | Observed execution duration in milliseconds. | `15002.4` |
| `dependency` | String | Yes | Target callee or database name. | `external-payment-partner` |
| `fingerprint` | String (16) | Yes | SHA-256 hash prefix of the normalized error template. | `f28a71c890ab43e1` |
| `redaction_applied`| Boolean | No | True if PII/PCI sensitive tokens were stripped from this entry. | `true` |
| `line_number` | Integer | No | Original 1-indexed line offset in uploaded log file. | `15` |

## 2. Core Relational Entities

### 2.1 `incidents`
Master record created for every ingested telemetry batch or simulation run.

| Field | Type | Description |
| :--- | :--- | :--- |
| `incident_number` | String | Human-readable unique identifier (e.g., `INC-2026-0001`). |
| `title` | String | Descriptive title assigned by engineer or scenario. |
| `severity` | Enum | Deterministically evaluated: `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`. |
| `status` | Enum | Lifecycle state: `OPEN`, `INVESTIGATING`, `MITIGATED`, `RESOLVED`, `CLOSED`. |
| `customer_impact` | Enum | Impact state: `CONFIRMED`, `SUSPECTED`, `UNKNOWN`. |
| `severity_rationale` | JSON | Rule-by-rule scoring breakdown and supporting event IDs. |

### 2.2 `error_patterns`
Clustered repeated error signatures generated by Module 4.

| Field | Type | Description |
| :--- | :--- | :--- |
| `fingerprint` | String | SHA-256 hash prefix of normalized template string. |
| `pattern_template` | Text | Token-masked error pattern (`<UUID>`, `<NUM>`, `<TXN_ID>`). |
| `occurrence_count` | Integer | Total frequency observed in dataset. |
| `sample_event_ids` | JSON | List of representative `event_id` citations. |

### 2.3 `hypotheses`
Evidence-grounded diagnostic explanations formulated by AI / heuristic engine.

| Field | Type | Description |
| :--- | :--- | :--- |
| `hypothesis_code` | String | Code identifier (e.g. `H-001`). |
| `title` | String | Concise title of proposed contributing factor. |
| `confidence` | Enum | Qualitative confidence: `HIGH`, `MEDIUM`, `LOW`. |
| `supporting_evidence_codes` | JSON | Array of verified `event_id` strings (`EVT-xxx`). |
| `verification_steps` | JSON | Step-by-step diagnostic checklist for on-call engineers. |
| `is_primary` | Boolean | True for the leading diagnostic hypothesis. |
